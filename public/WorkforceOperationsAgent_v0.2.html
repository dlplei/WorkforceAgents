一、建设目标

构建面向员工日常 HR 和企业内部服务场景的智能运营 Agent，使员工能够通过自然语言完成休假、调动、差旅、员工政策咨询、审批准备和 HR Service Request 等任务。

🧑‍💼 员工侧目标

  • 通过自然语言快速完成 HR 与内部服务任务
  • 获得结合个人情况的政策解释与流程建议
  • 减少查找制度、填写表单、追踪审批的时间成本

🏢 组织侧目标

  • 降低 HR 与运营团队重复咨询和工单处理压力
  • 提升政策执行一致性、流程合规性与审批材料质量
  • 形成员工服务统一入口与运营数据闭环
Agentic Workflow 企业知识与用户上下文融合 Memory Policy Grounding Tool Calling 流程自动化 Human-in-the-Loop

二、核心定位

与传统 HR Chatbot 不同，Workforce Operations Agent 不仅回答问题，还能够结合员工信息、企业政策和业务上下文，自主规划并推动相关流程执行。

能力维度传统 HR ChatbotWorkforce Operations Agent
交互方式问答式任务驱动式，多轮澄清与确认
信息来源静态 FAQ 或知识库知识库 + 员工上下文 + 流程状态 + 业务系统
执行动作通常提供链接或说明可调用 HRIS、OA、审批、差旅、工单等系统
流程能力简单指引规划、拆解、校验、提交、追踪和提醒
风险控制较弱权限边界、政策校验、人工审批、审计追踪
个性化较弱基于员工身份、岗位、地区、合同类型个性化响应
主动性被动响应主动推送提醒（假期到期、审批超时等）

三、典型业务场景

📅 1. 休假管理

员工通过自然语言完成请假申请、余额查询、假期类型推荐。

  • 自然语言请假："我下周三到周五想请年假"
  • 自动查询假期余额与政策合规性
  • 智能推荐最优请假方案（结合项目排期）
  • 自动生成审批材料并提交
  • 审批状态追踪与提醒

✈️ 2. 差旅管理

从出差申请到报销的全流程智能化服务。

  • 出差申请自动生成（基于会议/项目信息）
  • 差旅政策合规检查与超标预警
  • 机票酒店预订推荐（符合差标）
  • 行程单自动生成与审批
  • 报销单据智能整理与提交

🔄 3. 员工调动

支持跨部门、跨地区调动流程的智能化引导与执行。

  • 调动意向确认与政策匹配
  • 自动评估调动影响（薪酬、福利、社保）
  • 生成调动方案对比报告
  • 协调多部门审批流程
  • 调动后系统信息自动更新

涉及薪酬、合同、组织变更等高风险事项，必须引入 Human-in-the-Loop 审核。

📖 4. 政策咨询

基于企业政策知识库的精准问答与指引。

  • RAG 驱动的政策精准回答
  • 多轮对话澄清模糊需求
  • 个性化政策解读（结合员工身份）
  • 政策变更主动通知
  • 关联流程一键触发

政策类回答必须标明依据、适用范围、生效日期和限制条件。

✅ 5. 审批准备

智能准备审批材料，加速审批流程。

  • 自动收集审批所需信息
  • 生成结构化审批材料
  • 预检查审批通过概率
  • 审批人偏好适配
  • 催办与状态追踪

🎫 6. HR Service Request

各类 HR 服务请求的统一入口与智能处理。

  • 证明开具（在职/收入/离职）
  • 信息变更（银行卡/地址/紧急联系人）
  • 社保公积金咨询与办理
  • 入职/离职 Checklist 引导
  • 工单自动创建与追踪

五、核心模块设计

1. Agent Orchestration 层

系统核心，负责"理解、规划、执行、纠错"。

🧠 意图识别

识别政策咨询、休假申请、差旅申请、信息变更、调动流程、证明开具、工单查询、审批准备等意图。支持多轮对话澄清歧义。

📋 任务规划

将复杂目标拆分为身份校验、上下文获取、政策检索、流程校验、草稿生成、确认和提交等步骤。支持条件分支与并行执行。

🔀 Tool Router

根据任务步骤选择可用工具，并在调用前执行参数校验、权限校验和风险评估。

💾 Memory Manager

管理会话短期记忆、任务记忆和低敏偏好记忆，支持中断恢复和流程追踪。

📜 Policy Guard

确保政策回答基于检索结果，避免无依据生成（幻觉），并对不确定内容提示人工确认。

👤 HITL Engine

在高风险、低置信度、越权边缘或政策例外场景中引入员工、经理、HRBP、法务或财务审批。

七、Agent 工作流示例

基于 ReAct 模式的 Agentic Workflow：感知 → 规划 → 执行 → 确认 → 追踪

示例：员工申请年假

用户输入："我想 10 月 8 日到 10 月 10 日请年假，帮我申请。"

1. 识别意图：annual_leave_request
2. 获取员工身份：employee_id
3. 查询员工信息：地区、合同类型、入职时间、经理
4. 查询假期余额
5. 检索年假政策
6. 校验日期和余额
7. 检查是否需要提前申请 / 日历冲突
8. 生成申请草稿
9. 展示给员工确认 (Human-in-the-Loop)
10. 员工确认后调用 Leave Request API
11. 创建审批流
12. 返回申请编号，设置状态追踪

（若需要调整日期或证明语言版本，可点击【修改诉求】快速微调，智能体将立即重新生成对应卡片）

八、数据流与上下文融合

Agent 如何将员工信息、企业政策、业务上下文有机融合，驱动智能决策。

上下文融合架构 (Context Fusion)

📥 输入上下文

  • 员工 Profile：职级、部门、地点、入职日期、假期余额
  • 组织上下文：团队结构、汇报关系、项目归属
  • 对话历史：当前会话 + 近期交互记录
  • 业务日历：项目里程碑、团队排期、公司假期

🧠 Context Fusion Engine

  • 上下文注入 (Context Injection)
  • 相关性排序 (Relevance Ranking)
  • 冲突检测 (Conflict Detection)
  • Prompt 增强 (Prompt Augmentation)

📤 增强输出

  • 个性化回答：基于员工身份定制
  • 可执行方案：含具体步骤和预估时间
  • 风险提示：政策冲突、时间冲突预警
  • 关联推荐：后续操作建议

九、Memory 系统设计与 Redis 缓存治理

🔵 工作记忆与问答缓存 (Working Memory & Cache)

当前会话上下文短期保持，以及高频问答毫秒级秒回与流式回放。

技术：Redis (DB 1) + In-Context Window + 分级 TTL

生命周期：动态分级 (10m / 1h / 24h) / 会话期间 / 写时主动淘汰

🟣 情景记忆 (Episodic Memory)

历史交互记录，支持检索。

技术：Vector DB + PostgreSQL

生命周期：永久（可定期清理）

🔷 语义记忆 (Semantic Memory)

企业政策、流程知识。

技术：Vector DB + Elasticsearch

生命周期：随政策更新

🟢 用户画像 (User Profile Memory)

员工偏好、行为模式。

技术：PostgreSQL + Cache

生命周期：随 HRIS 同步

隐私边界：不可长期记忆的信息

⚠️ 以下信息严禁写入长期记忆：
  • 健康信息、医疗证明
  • 家庭成员隐私详情
  • 薪资细节与薪酬谈判记录
  • 证件号码（身份证、护照等）
  • 敏感绩效信息与纪律处分记录
  • 银行卡号等金融信息

⏱️ 1. 动态分级 TTL 策略 (Tiered TTL)

按数据实效性智能评级

  • 静态企业政策（24h / 86400s）：休假制度、差旅差标、通用合规手册，政策变动频率低，长周期安全缓存；
  • 电子证明开具（1h / 3600s）：在职证明、收入证明等生成型文档，兼顾短时重复下载与员工最新就职信息时效；
  • 个人动态业务数据（10min / 600s）：年假余额查询、审批流进度、工单状态等强实时数据，采用短 TTL 兜底。

🧹 2. 写操作主动失效联动 (Evict-on-Write)

业务动作驱动精准淘汰

  • 写操作识别：当 Agent 成功调用写工具（如 submit_leave_request、create_service_ticket、cancel_service_ticket）时自动触发；
  • 联动清除策略：精准清除受影响维度的缓存（如提交请假后，自动淘汰个人年假余额及“年假/请假/假期/余额”提问缓存），彻底杜绝数据更新后读取旧缓存；
  • 只读缓存安全保留：通用规章等静态政策缓存不受波及。

🛡️ 3. 隔离与防 OOM 物理兜底 (LRU Eviction)

容器资源多租户安全

  • 独立 DB 隔离：接入宿主 Redis 容器但严格配置独立 DB 1 与 workforce:cache:* 键前缀，完全杜绝与宿主其他微服务键冲突；
  • 规范化模糊命中：自动对提问做去标点与空格清洗，支持中英文全半角标点模糊匹配；
  • LRU 内存兜底：配合 maxmemory-policy: volatile-lru，优先淘汰最近最少使用的带过期时间缓存，彻底避免生产 OOM。

🔄 4. 客户端主动控制与人机协同闭环

用户体验与强制重算

  • 单条消息「重新生成」：在 Assistant 回复气泡右下角增加重新生成按钮，携带 force_refresh: true 直通大模型重新推理并覆写缓存，解决用户需要最新生成答案的需求；
  • 全局「清空 Redis 缓存」：在界面顶部工具栏新增清空缓存按钮，调用 POST /api/cache/clear，并弹出轻量 Toast 提示清空条目数；
  • 秒回视觉动效：针对命中的缓存，前端展示「⚡ Redis 缓存秒回」徽章，并完整平滑回放逐字流式打字与工具调用状态。

🛡️ 1. 图内拦截挂起与 Trace 时序保真

💡 架构决策洞察（为什么不在 LangGraph 图内加路由节点？）：
若在 LangGraph 图内部新增一个意图分类节点（Router），通常需额外调度一次 LLM 或 SLM 判别，导致哪怕是简单的攻击刺探或日常问候，都会徒增 300~800ms 的模型推理耗时与 Token 成本。

十六、优先建设建议

  1. 企业政策 RAG 问答：覆盖员工手册、休假政策、差旅政策、福利政策。
  2. 员工上下文服务：对接 HRIS，读取员工基本信息、组织关系、休假余额。
  3. 休假申请 Agent：作为第一个端到端流程型场景，复杂度适中、价值明显。
  4. HR Service Request Agent：支持创建、分类、查询 HR 工单。
  5. 审批前检查能力：自动检查材料完整性、政策符合性和审批路径。
  6. HITL 审批机制：对高风险事项引入人工确认和审批。

十七、方案总结

Workforce Operations Agent 的核心不是简单 HR 问答，而是一个结合企业知识、员工上下文、流程自动化和权限治理的智能运营系统。

它应能够：
✅ 理解员工自然语言需求
✅ 检索并引用企业政策
✅ 结合个人上下文给出个性化判断
✅ 拆解并推进流程
✅ 调用企业系统执行操作
✅ 在关键节点请求员工确认或人工审批

通过分阶段实施、持续迭代优化，最终实现员工服务体验的全面提升和 HR 运营效率的显著增长。
