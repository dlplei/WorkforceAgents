一、建设目标

构建面向员工日常 HR 和企业内部服务场景的智能运营 Agent，使员工能够通过自然语言完成休假、调动、差旅、员工政策咨询、审批准备和 HR Service Request 等任务。

员工侧目标

  • 通过自然语言快速完成 HR 与内部服务任务。
  • 获得结合个人情况的政策解释与流程建议。
  • 减少查找制度、填写表单、追踪审批的时间成本。

组织侧目标

  • 降低 HR 与运营团队重复咨询和工单处理压力。
  • 提升政策执行一致性、流程合规性与审批材料质量。
  • 形成员工服务统一入口与运营数据闭环。
Agentic Workflow 企业知识与用户上下文融合 Memory Policy Grounding Tool Calling 流程自动化 Human-in-the-Loop Approval

二、核心定位

与传统 HR Chatbot 不同，Workforce Operations Agent 不仅回答问题，还能够结合员工信息、企业政策和业务上下文，自主规划并推动相关流程执行。

能力维度 传统 HR Chatbot Workforce Operations Agent
交互方式问答式任务驱动式，多轮澄清与确认
信息来源静态 FAQ 或知识库知识库 + 员工上下文 + 流程状态 + 业务系统
执行动作通常提供链接或说明可调用 HRIS、OA、审批、差旅、工单等系统
流程能力简单指引规划、拆解、校验、提交、追踪和提醒
风险控制较弱权限边界、政策校验、人工审批、审计追踪
个性化较弱基于员工身份、岗位、地区、合同类型个性化响应

三、典型业务场景

1. 休假服务

员工可发起休假咨询与申请，例如“我下周想请 3 天年假，可以帮我看看是否符合政策并发起申请吗？”

  1. 识别休假申请意图。
  2. 获取员工地区、合同类型、入职时间、假期余额等上下文。
  3. 检索年假政策并校验申请条件。
  4. 生成申请摘要，请员工确认。
  5. 调用休假系统创建申请并提交审批。

2. 差旅申请

员工可要求 Agent 准备差旅申请、检查差旅标准、生成审批材料。

  • 收集出行日期、目的地、预算、客户名称、业务目的等信息。
  • 检索住宿、交通、餐补等差旅政策。
  • 判断是否超标，必要时进入例外审批。

3. HR 政策咨询

结合员工所在地区、员工类型、入职时间、福利资格等上下文，返回个性化政策解释。

政策类回答必须标明依据、适用范围、生效日期和限制条件。

4. 员工调动 / 转岗

为 HRBP 或经理准备内部调动流程，检查权限、组织关系、审批矩阵、岗位变化和合规要求。

涉及薪酬、合同、组织变更等高风险事项，必须引入 Human-in-the-Loop 审核。

五、核心模块设计

1. 员工交互入口层

支持多渠道接入与一致化用户体验，处理身份识别、多轮对话、消息上下文保留、文件上传解析、审批通知与状态提醒。

Microsoft Teams Slack 企业微信 飞书 Web Portal Mobile App

2. Agent Orchestration 层

系统核心，负责“理解、规划、执行、纠错”。

意图识别

识别政策咨询、休假申请、差旅申请、信息变更、调动流程、证明开具、工单查询、审批准备等意图。

任务规划

将复杂目标拆分为身份校验、上下文获取、政策检索、流程校验、草稿生成、确认和提交等步骤。

Tool Router

根据任务步骤选择可用工具，并在调用前执行参数校验、权限校验和风险评估。

Memory Manager

管理会话短期记忆、任务记忆和低敏偏好记忆，支持中断恢复和流程追踪。

Policy Guard

确保政策回答基于检索结果，避免无依据生成，并对不确定内容提示人工确认。

HITL Engine

在高风险、低置信度、越权边缘或政策例外场景中引入员工、经理、HRBP、法务或财务审批。

3. 企业知识与 Policy Grounding 层

6. Memory 设计

短期记忆

当前会话中的申请类型、日期、已补充信息、待确认事项。

任务记忆

跨会话继续流程，如未提交差旅申请、待补充材料工单。

长期偏好记忆

仅保存低敏偏好，如常用语言、默认办公地、常用出发城市。

不可长期记忆

健康信息、家庭成员隐私、薪资细节、证件信息、医疗证明、敏感绩效信息。

六、Agent 工作流示例：员工申请年假

用户输入：“我想 10 月 8 日到 10 月 10 日请年假，帮我申请。”

1. 识别意图：annual_leave_request
2. 获取员工身份：employee_id
3. 查询员工信息：地区、合同类型、入职时间、经理
4. 查询假期余额
5. 检索年假政策
6. 校验日期和余额
7. 检查是否需要提前申请
8. 生成申请草稿
9. 展示给员工确认
10. 员工确认后调用 Leave API
11. 创建审批流
12. 返回申请编号

Agent 回复示例

我已检查你的年假余额和公司年假政策。你当前剩余年假为 7 天，计划申请 2026 年 10 月 8 日至 10 月 10 日，共 3 个工作日，符合《员工年假管理办法》的申请条件。

申请摘要如下：
- 假期类型：年假
- 日期：2026-10-08 至 2026-10-10
- 天数：3 天
- 审批人：你的直属经理王经理

请确认是否提交该申请？

七、安全、权限与治理

1. Human-in-the-Loop Approval

场景处理方式
政策不明确转 HR 专员确认
信息不完整请求员工补充
超出政策标准进入例外审批
涉及薪酬或合同HRBP 或经理审核
涉及敏感个人信息加强身份和权限校验
高影响组织变更多级审批
Agent 置信度低人工复核后再执行
 
Agent 生成申请/建议
  ↓
员工确认
  ↓
系统校验风险等级
  ├─ 低风险：自动提交审批流
  ├─ 中风险：经理审批
  └─ 高风险：HRBP / 法务 / 财务复核

2. 身份认证与权限控制

集成企业 IAM，支持 SSO、OAuth 2.0 / OpenID Connect、企业 AD / Entra ID、多因素认证 MFA。

RBAC：基于角色

  • 普通员工
  • 直属经理
  • HR 专员
  • HRBP
  • 财务审批人
  • 系统管理员

ABAC：基于属性

  • 所属国家 / 地区
  • 部门与成本中心
  • 员工类型
  • 汇报关系
  • 数据敏感级别
  • 操作类型与审批链关系

3. Guardrails

输入侧防护

  • Prompt Injection 检测
  • 越权查询检测
  • 敏感信息识别
  • 上传文档安全扫描

推理侧防护

  • 政策回答必须基于检索结果
  • 工具调用前参数校验
  • 高风险任务人工确认
  • 权限判断前置

输出侧防护

  • 避免暴露无权限数据
  • 敏感字段脱敏
  • 标注政策依据
  • 明确不确定边界

八、实施路线图

阶段一：MVP（建议 6-10 周）

目标：覆盖高频低风险场景。

  • HR 政策问答
  • 年假余额查询
  • 休假申请草稿生成
  • HR 工单创建
  • 审批状态查询

能力：基础 RAG、员工身份认证、员工上下文读取、工具调用、员工确认后提交申请。

阶段二：流程型 Agent（建议 8-12 周）

目标：从问答升级到流程推进。

  • 差旅申请
  • 证明开具
  • 员工信息变更
  • 入职服务与离职服务
  • 转岗 / 调动流程准备

能力：多步骤任务规划、流程状态记忆、HITL、审批材料自动生成、异常补充信息收集。

阶段三：智能运营优化（持续迭代）

目标：形成主动式 HR 运营能力。

  • 假期即将过期主动提醒
  • 新员工入职任务跟进
  • 审批超时提醒
  • HR 工单自动分类和分派
  • 高频问题洞察与员工服务体验分析

九、衡量指标

员工体验指标

  • 首次响应时间
  • 任务完成时间
  • 员工满意度
  • 自助解决率
  • 多轮对话完成率

运营效率指标

  • HR 工单减少比例
  • 人均服务成本降低
  • 自动化流程提交比例
  • 审批材料一次通过率
  • HR 专员处理时长降低

质量与安全指标

  • 政策回答准确率
  • 工具调用成功率
  • 越权访问拦截率
  • 人工介入率
  • 审计覆盖率
  • 幻觉率或无依据回答率

十、推荐优先建设能力与总结

优先建设能力

  1. 企业政策 RAG 问答：覆盖员工手册、休假政策、差旅政策、福利政策。
  2. 员工上下文服务：对接 HRIS，读取员工基本信息、组织关系、休假余额。
  3. 休假申请 Agent：作为第一个端到端流程型场景，复杂度适中、价值明显。
  4. HR Service Request Agent：支持创建、分类、查询 HR 工单。
  5. 审批前检查能力：自动检查材料完整性、政策符合性和审批路径。
  6. HITL 审批机制：对高风险事项引入人工确认和审批。
Workforce Operations Agent 的核心不是简单 HR 问答，而是一个结合企业知识、员工上下文、流程自动化和权限治理的智能运营系统。它应能够理解员工自然语言需求、检索并引用企业政策、结合个人上下文给出个性化判断、拆解并推进流程、调用企业系统，并在关键节点请求员工确认或人工审批。
